# 屏幕二维码传输系统

用电脑屏幕作为传输介质：发送端把 TXT 文件拆成一块块二维码，生成循环播放的视频；接收端用摄像头拍摄屏幕，或读取手机录制的视频，识别二维码并还原 TXT。整个过程不依赖网络、U 盘或数据线。

## 文件

- `二维码编码.py`：发送端命令行，核心代码已精简
- `二维码编码界面.py`：发送端图形界面
- `二维码解码.py`：接收端命令行
- `二维码解码界面.py`：接收端图形界面
- `README.md`：本文档

## 安装

```bash
python -m pip install qrcode[pil] opencv-python zxing-cpp
```

## 快速开始

1. 编码 TXT：

```bash
python 二维码编码.py 测试.txt
```

生成 `测试.txt.qr.mp4`。

2. 全屏循环播放该视频。建议使用播放器的“循环播放”模式。

3. 接收：

```bash
# 摄像头对准屏幕实时解码
python 二维码解码.py --camera 0

# 解析手机拍摄的视频文件
python 二维码解码.py 手机录像.mp4
```

默认输出名为 `手机录像还原.txt`，全部二维码到齐且 CRC 校验通过后写入。

## 发送端参数

```bash
python 二维码编码.py 文件.txt -s 100 -e H -r 2 -q 5 --size 1080
```

- `-s`：每块字节数，默认 100。越小二维码越小、越抗噪，但块数更多。
- `-e`：纠错级别 L/M/Q/H，默认 H，抗干扰最强。
- `-r`：每张二维码的重复帧数，默认 2，起时间冗余作用。
- `-q`：每秒切换的二维码张数，默认 5，可自定义发送速度。
- `--size`：视频画面边长，默认 1080。
- `--gif`：同时生成 GIF 版本。
- `-o`：自定义输出视频路径。

示例：每秒 3 张二维码，适合手机距离屏幕较远时使用。

```bash
python 二维码编码.py 文件.txt -q 3
```

## 工作原理

- 文件字节按 `-s` 切成若干块，每块封装 19 字节头：魔数、协议版本、块总数、块序号、块长度、整文件 CRC、块 CRC。
- 每块生成一张二维码，视频按每秒 `-q` 张的速度循环播放。
- 接收端逐帧识别二维码，按序号自动去重、补齐，不要求按顺序播放。
- 全部块到齐后重组，并做双重 CRC 校验，校验通过才写入还原文件。

## 屏幕传输要点

- 视频一定要循环播放，录制时建议录 2 到 3 个完整循环，缺帧也能补齐。
- 摄像头尽量正对屏幕，避免倾斜、反光和过曝。
- 解码不依赖视频帧率，手机以 24/30/60fps 摄录都能还原。
- 播放时不要拉伸、缩放得过小，保证二维码模块清晰。

## 常见问题

- `Permission denied`：输出文件正被播放器或文本编辑器占用。关闭占用程序后重试；代码已保证写入异常时释放视频文件句柄。
- 一直缺帧：降低 `-q`（例如改为 3），多录几个循环，或让屏幕更清晰。
- 二维码模糊：使用更小的 `-s`，并确认播放器没有过度压缩画面。
- 无法打开视频：确认 OpenCV 能解码该格式，尽量使用 MP4。

## 推荐参数

- 默认场景：`-s 100 -e H -r 2 -q 5`
- 手机摄录：`-q 2~5`
- 大文件：`-s 200~300`，但需要更大的屏幕和更清晰的拍摄
